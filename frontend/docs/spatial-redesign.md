# بازطراحی Spatial Atelier

> این گزارش مربوط به تحویل بصری اولیه است. اصلاحات بعدی ورود و مسیر برگشت پرداخت در `routing-security-fix.md` ثبت شده‌اند.

## محدودهٔ تحویل

بازطراحی فرانت مشتریان در برنچ `feat/spatial-storefront`؛ بدون تغییر Django، API، مدل‌ها، migrationها، منطق قیمت/موجودی/رزرو/پرداخت، JWT یا سیاست retry مالی. Django Admin و قالب‌های legacy بک‌اند بازطراحی نشده‌اند. این کار استقرار production نیست.

- Hero جدید با **مدل حجمی واقعی WebGL**، Three.js و React Three Fiber؛ نور، سایه، متریال فیزیکی با sheen، چرخش نسبی، بازنشانی و توقف/شروع حرکت. توقف، زاویهٔ قابل مشاهده را نگه می‌دارد؛ reset جداست.
- مدل Microsoft SheenCloth با مجوز CC0، سبک‌شده به ۱۳٬۸۲۴ مثلث / ۷٬۳۹۳ رأس؛ دادهٔ هندسه **۳۱۹٬۵۲۸ بایت**، بدون وابستگی به CDN. این **مطالعهٔ فرم و پارچه است، نه مدل محصول قابل فروش**. برای نمایش ۳۶۰ درجهٔ هر لباس، مدل معتبر همان محصول لازم است.
- تغییر بصری صفحات اصلی، کاتالوگ، جزئیات محصول، سبد، ورود، ثبت سفارش، نتیجهٔ پرداخت، حساب/پروفایل/آدرس/سفارش‌ها/علاقه‌مندی‌ها/اعلان‌ها و خطاها از طریق اجزای مشترک و tokenهای موجود؛ حالت روشن/تیره مطابق دستگاه.
- Tilt واقعی 21st (ibelick، demo 1448) با Motion موجود، نه نصب هم‌زمان framer-motion. کارت‌ها با موس عمق می‌گیرند؛ فرم‌های مالی نمی‌چرخند. demo 6563 بررسی شد اما مسیر HTML خام/راهروی ثابت آن وارد production نشد.
- اسکیل UI UX Pro Max با منبع pinned و موتور واقعی اجرا شد؛ تصمیم‌های بررسی‌شده در `design-system/onlineshop-plus/MASTER.md` آمده‌اند. خروجی‌های نامتناسب موتور عیناً کپی نشده‌اند.

## معماری و عملکرد

Next به‌عنوان پوستهٔ BFF/احراز هویت/مسیرها حفظ شد؛ محدودیت گرافیک نیست. موتور بصری از پایه در `features/showroom/` با R3F/Three.js ساخته شده است. رهاکردن زیرساخت auth صرفاً برای تغییر نام framework فایده‌ای برای 3D نداشت.

Scene به‌صورت lazy/client-only و same-origin لود می‌شود؛ DPR حداکثر ۱٫۵، سایهٔ ۱۰۲۴، رندر demand-driven، توقف کار پیوسته خارج viewport یا تب پنهان. تغییر کنترل‌ها renderer را صریحاً بیدار می‌کند. reduced-motion زنده مانع حرکت خودکار مدل و دوربین است؛ دکمه‌های عمدی همچنان کار می‌کنند. Save-Data از بارگیری صحنه جلوگیری می‌کند. خطا/نبود WebGL یا context loss تصویر ثابتِ رندرشده از **همین مدل** را نگه می‌دارد. scroll بومی است؛ Lenis/GSAP قبلی در صفحهٔ اصلی import نمی‌شوند.

بازتولید فایل‌های binary با `prepare-assets.mjs` از base64 محلی و SHA-256 انجام می‌شود؛ build به کلید 21st، دریافت مدل بیرونی یا ابزار بهینه‌سازی نیاز ندارد. binaryها generated/ignored هستند. منبع و CC0 در `SheenCloth-CC0.md` و MIT کامپوننت در `motion-primitives-LICENSE.txt` نگهداری شده‌اند.

## اصلاحات همراه

- ناهماهنگی hydration وقتی cache دسته‌ها پیش از hydrate شدن صفحهٔ streamشده توسط Header پر می‌شد، با snapshot پایدار سرور رفع شد.
- آزمون سفارش ambiguous منتظر مشاهدهٔ واقعی request می‌ماند؛ عبور فوری UI به recovery دیگر به‌اشتباه به معنی ارسال کامل درخواست فرض نمی‌شود. رفتار مالی runtime تغییر نکرد.
- Next از 16.4.0 به **16.4.3** و fast-uri transitive به نسخهٔ وصله‌شده ارتقا یافتند؛ `npm audit` نهایی **صفر آسیب‌پذیری گزارش‌شده** داشت. این تضمین امنیت آینده یا pentest نیست.

صفحات و حالت‌های اصلی در desktop/mobile رندر شدند؛ نماهای مدل، متریال و viewport موبایل و صفحات خرید/حساب/خطا به‌صورت تصویری بازبینی شدند. تصاویر و پیش‌نمایش ویدئویی QA، دادهٔ نمونه‌اند، نه کاتالوگ یا موجودی واقعی. WebGL محیط CI/headless ممکن است software-rendered باشد؛ این اندازه‌گیری FPS یا GPU موبایل واقعی نیست.

## اجرا‌نشده / پیش از انتشار

- Journey واقعی Django، تست Redis واقعی، PostgreSQL/concurrency، درگاه یا SMS واقعی در این دور اجرا نشده‌اند. نتایج تاریخی گزارش قبلی را جای نتیجهٔ این دور قرار ندهید.
- Lighthouse جدید، اندازه‌گیری روی موبایل واقعی، Safari/Firefox/WebKit، iOS/Android، screen-reader انسانی و تست چند replica/staging انجام نشده‌اند. هیچ امتیاز performance یا ۶۰fps تضمین نشده است.
- محدودیت‌های قبلی callback/آدرس عمومی درگاه/trusted IP و سایر موارد deployment همچنان برقرارند؛ به `deployment-checklist.md` و گزارش قبلی رجوع کنید.
- GLB واقعی محصولات، برند/سیاست‌های تأییدشده و دادهٔ production همچنان باید از مالک دریافت شوند. هیچ امتیاز/موجودی/تضمین یا عکس محصولی ساخته نشده است.
- PR برای بررسی ظاهر و کد است؛ merge و deploy انجام نشده‌اند.
