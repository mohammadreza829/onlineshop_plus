# گزارش بازطراحی مدرن فرانت

## محدوده و تصمیم‌ها

این گزارش جایگزین وضعیت ظاهری و QA جاری در گزارش تاریخی `FRONTEND_IMPLEMENTATION.md` است. مبنای GitHub: `21bc2e0e71b23973f5780f89fa3507006905c898` (main پس از merge PR8). کد روی شاخهٔ `frontend/modern-redesign` آمادهٔ review است؛ merge و deploy بخشی از این گزارش نیستند.

- ظاهر روشن و مینیمال، اکشن‌های نزدیک به مشکی، accent سبز خنثی، تایپوگرافی فارسی، hero تصویری و فاصله‌بندی یکپارچه؛ کاتالوگ، محصول، سبد، ورود، checkout و حساب از foundation مشترک استفاده می‌کنند.
- تصویر hero اختصاصاً با AI تولید شده، حدود ۲۵KB WebP، کاملاً local و تزئینی است؛ **عکس محصول نیست** و همین تفاوت در UI نوشته شده است. محصولات همچنان فقط از API Django می‌آیند. نبود تصویر در API با placeholder صادقانه نشان داده می‌شود.
- React/Next/TypeScript، TanStack Query، RHF/Zod و Radix حفظ شدند؛ اضافه‌کردن کتابخانهٔ بیشتر هدف نبود. انیمیشن‌های کوتاه CSS و اسکرول native جای حرکت سنگین hero و Motion runtime را گرفتند. dependencyهای قبلی GSAP/Lenis/Motion فعلاً در lockfile هستند، اما runtime جدید آن‌ها را import نمی‌کند.
- focus trap، Escape، بازگشت focus و scroll lock پنل‌ها با Radix؛ focus ring واضح، کنترل لمسی حداقل ۴۴px و احترام به reduced-motion حفظ شد.
- شناسهٔ سفارش روی موبایل دیگر وسط `ORD-…` شکسته نمی‌شود؛ فاصله‌های فرم فیلتر و دکمه‌های آن اصلاح شد.
- `setup:dev` تنها در توسعه تنظیمات مفقود و secret تصادفی محلی می‌سازد، گزینه‌های قبلی و env با اولویت بالاتر را حفظ می‌کند و secret چاپ نمی‌کند. memory برای dev تک‌فرآیندی صریح است؛ production همچنان Redis مشترک/HTTPS/تنظیمات صریح می‌خواهد.
- `doctor` origin/secret و اتصال فقط‌خواندنی Django/Redis را بررسی می‌کند. 503 تنظیمات توسعه پیام قابل اقدام دارد؛ قطع کاتالوگ با empty state اشتباه گرفته نمی‌شود.

### بررسی تصویری و راه‌اندازی اولیه

۱۶ مسیر در عرض‌های ۱۴۴۰ و ۳۹۰، کاتالوگ در عرض‌های ۳۶۰/۷۶۸/۱۰۲۴ و پنل‌های موبایل render شدند: ۳۷ capture اولیه، ۳۵ بررسی خودکار عرض بدون overflow و صفر page exception. PNGها تک‌به‌تک بازبینی شدند؛ شکستگی شناسهٔ سفارش و فشردگی فیلتر اصلاح و دوباره render/بازبینی شدند. ۹ capture هدفمند دیگر، شامل home نهایی، شناسهٔ اصلاح‌شده، پنل‌ها و حالت قطع واقعی بک‌اند، بررسی شد. captureهای قدیمی معیار نسخهٔ اصلاح‌شده نیستند.

اجرای بار اول در پوشهٔ جدا با **بدون env قبلی** نیز تست شد: `npm run dev` تنظیم محلی ساخت و Next/Turbopack روی 127.0.0.1:3000 آماده شد. Django در پورت پیش‌فرض 8000 عمداً خاموش بود؛ doctor همان را گزارش داد، home با 200 و تنها یک بلوک خطای کاتالوگ/یک alert، بدون overflow یا page exception نمایش داده شد. با تنظیم Django ایزولهٔ فعال، تست جریان واقعی بالا پاس شد. این نتیجه به معنی روشن‌شدن خودکار Django روی لپ‌تاپ مالک نیست.

اولین تست محیط به‌علت نبود Redis نصب‌شده در sandbox شکست خورد؛ Redis فقط برای QA ایزوله نصب و suite کامل دوباره پاس شد. تست اولیه با symlink وابستگی‌ها خارج از root محدود Turbopack هم شکست خورد؛ با چیدمان واقعی dependencyهای محلی تکرار و اجرای اولیه تأیید شد. این تغییرات ابزار تست به کد runtime اضافه نشدند.

### Lighthouse موبایل

اجرای production محلی، Chromium، شبیه‌سازی پیش‌فرض موبایل/شبکهٔ Lighthouse، دادهٔ ایزولهٔ Django:

- Performance: **۸۸/۱۰۰**
- Accessibility: **۱۰۰/۱۰۰**
- Best Practices: **۱۰۰/۱۰۰**
- SEO: **۱۰۰/۱۰۰**
- LCP: **۳٫۲ ثانیه**؛ CLS: **۰٫۰۰۵**؛ TBT: **۲۶۰ms**.

این اندازه‌گیری آزمایشگاهی است، نه Web Vitals کاربران واقعی یا تضمین سرعت production. هدف LCP زیر ۲٫۵ ثانیه **هنوز محقق نشده**. اجراهای حین توسعه/بازآزمایی در همین محیط Performance ۸۴ تا ۸۸ و LCP حدود ۳٫۴ ثانیه داشتند؛ پس ادعای ثبات امتیاز یا رسیدن به تمام بودجه‌های کارایی مطرح نیست. تصویر بهینه و دانلود فونت لاتین حذف شد؛ بهینه‌سازی بیشتر bundle و سنجش روی زیرساخت نهایی باقی است.

## مسئله‌های لپ‌تاپ و محدودیت‌های باقی‌مانده

- `503` لاگ ارسال‌شده به‌تنهایی علت قطعی را مشخص نمی‌کرد. backend خاموش، origin/secret ناقص یا Redis انتخاب‌شده و خاموش می‌توانند مطرح باشند. راه‌اندازی جدید و doctor این وضعیت را قابل تشخیص می‌کنند؛ جای اجرای Django را نمی‌گیرند.
- `data-bidi` و style تزریق‌شدهٔ RTL در source پروژه یافت نشد. افزونهٔ مرورگر علت محتمل است، نه اثبات قطعی روی دستگاه مالک؛ با پروفایل بدون افزونه تست شود. Hydration warning سرکوب نشده است.
- تست روی **Chromium/Linux** است؛ Safari/Firefox/دستگاه واقعی و محیط Windows مالک مستقلاً تأیید نشده‌اند. راهنمای PowerShell نوشته شده ولی اجرای مستقیم روی لپ‌تاپ مالک در دسترس نبود.
- backend business logic، مدل‌ها، migrationها، منطق قیمت/موجودی/پرداخت و API contract تغییر نکردند. callback درگاه هنوز صفحهٔ Django است؛ redirect خودکار تأییدشده به Next و trusted-IP پشت BFF نیازمند کار مستقل بک‌اند و تأیید مالک‌اند.
- هیچ SMS، درگاه یا سفارش production استفاده نشد. هیچ استقرار، ادعای pentest، تضمین حقوقی تصویر AI یا تضمین «صفر باگ» انجام نشده است.
- تست‌های این گزارش **محلی** هستند؛ GitHub hosted CI از این ابزار به‌علت محدودیت دسترسی check/status قابل تأیید نبوده است. نبود access را با سبزبودن CI یکی نمی‌دانیم.
