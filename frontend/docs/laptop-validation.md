# Laptop profile and demo catalogue — validation addendum

This extends the original redesign. Unlike the earlier frontend-only scope, this explicitly requested change adds local backend configuration, a guarded demo seed, a development-only payment-disable adapter and an additive catalogue API thumbnail. No production provider, security check, model or migration was removed.

## Delivered source

- `manage_laptop.py` / `onlineshop/laptop_settings.py`: explicit single-process, loopback development; dedicated `.local/laptop.sqlite3`, `.local/media`, persistent random secrets, SQLite, LocMem cache, synchronous console SMS. No Redis/PostgreSQL/worker needed for this profile. Existing `.env`, `db.sqlite3` and production settings remain separate.
- Local OTP logger is deliberately plaintext **only for `account.sms` in this explicit profile**, with a `LOCAL DEVELOPMENT ONLY` prefix and no propagation. All other JSON logs retain redaction. Ordinary production logs still redact OTP/phone values. The initial real-profile journey caught that the global JSON formatter hid development OTPs; the scoped local logger fixes this without exposing codes through an API or frontend.
- `seed_demo`: 6 labelled categories, 36 labelled synthetic products, 36 offline-generated WebP garment illustrations, 96 variants, discounts, sold-out cases and `DEMO10` (10%). Generated prices/inventory/features are test data, not real offers or product photographs. Newest-first creation timestamps interleave categories. No orders/accounts/default passwords are seeded.
- Guard requires DEBUG + explicit demo marker + matching dedicated SQLite database. Namespaced collision preflight, atomic database writes and cleanup of newly written media on failure. Rerun is additive: no resets, deletes, duplicate products or overwritten stock/edits.
- Local payment adapter never contacts a gateway, returns a controlled request rejection and UNKNOWN verification; it never marks orders paid. Its factory guard additionally requires DEBUG. Production Zarinpal/SMS.ir behavior and checks remain present.
- `npm run dev:local`: Windows-compatible Node child-process launcher; fixed matching 127.0.0.1 origins (3000/8000), private local BFF secret and memory coordinator. Existing env files are not rewritten; production mode is refused. These are development commands, not a replacement for production Redis/TLS.
- Catalogue list now includes nullable `image`; one SQL query with an ordered image subquery, not a DB query/detail HTTP fetch per card. Card detail fetches were removed. Same-origin image URL mapping is shared between BFF and SSR initial data; unapproved image hosts remain rejected. OpenAPI snapshot updated. No migration required.
- Complete Windows commands and runtime caveats: `docs/laptop-setup.md`.

Includes 9 new tests for profile isolation, visible local OTP, no SMS HTTP, disabled-payment safety, production adapter selection, seed guard/collisions/idempotence, preserved existing data and image query/selection behavior.
- Backend Ruff lint and format check pass; Django system check and migrations pass.
- Frontend ESLint, strict TypeScript and production build pass.
- Vitest: **66 passed, no skips**, including actual isolated Redis coordination regression and 4 new laptop/image-mapping tests. Redis here is test infrastructure for the unchanged production coordinator, NOT a laptop runtime requirement. Without Redis configured, the earlier laptop run had 65 passed/1 intentionally skipped.
- Playwright: **22 passed** in the standard isolated production-build QA environment (Next :3100, Django harness :8100, Redis :6381). One real-backend test uses test-double OTP transport/randomness/gateway; 21 are controlled UI/mock checks. No external SMS or money. An initial run against the laptop demo server instead of the prescribed QA fixture server failed 3/21 checks (missing qa-simple SSR record, fixed expected QA origin and a product-dependent axe setup); the full suite was rerun with its documented environment and passed without weakening those tests.
- Additional **actual laptop profile** HTTP journey on :3000/:8000: random OTP generated by the real backend and read from the local terminal; authenticated BFF cookies; real session cart/variant, address, DEMO10, order creation. Payment initiation returned HTTP 400 with the local-disabled message; order remained unpaid. No fixed test OTP or fake-success gateway was used for this journey.
- Fresh separate SQLite seed run created 36 products; second run created 0. Automated tests also preserve an unrelated product and manually changed inventory across reruns.
- Six final captures individually reviewed: home/catalogue/product at 1440 and 390px, using real seeded data and local images. No page overflow, JS page errors, hydration warning, broken image or 429/5xx observed in the final capture run. ## Boundaries

Testing was Linux/Chromium, not direct execution on the owner's Windows laptop, Safari or Firefox. No external provider, production deployment, production catalogue, live payment or public release was tested. The earlier Lighthouse result is historical and **not remeasured for the 36-product catalogue**. Hosted GitHub checks were previously inaccessible with this token (403); local passes are not proof of hosted CI. No guarantee of zero bugs or production readiness. Existing public callback/IP-proxy integration work remains separate.

Keep both local servers running. Local cache/OTP state resets on backend restart; no Celery scheduler runs. Use `manage_laptop.py expire_orders` manually when testing expired reservations. Do not expose the laptop profile or its plaintext OTP terminal logs publicly.
