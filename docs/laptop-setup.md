# اجرای لپ‌تاپ — Windows / PowerShell

این پروفایل **فقط برای توسعه روی دستگاه خودتان** است، نه سرور عمومی یا production.

## چه چیزهایی جدا شده‌اند؟

- `manage_laptop.py` همیشه `onlineshop.laptop_settings` را انتخاب می‌کند. خطای `SMS_IR_API_KEY` در این مسیر رخ نمی‌دهد: پیامک واقعی خاموش و OTP در ترمینال جنگو چاپ می‌شود. کد واقعی تصادفی است، نه کد ثابت تست.
- SQLite در `.local/laptop.sqlite3`، تصاویر در `.local/media` و secretهای تصادفی پایدار در `.local/` هستند. به `db.sqlite3`، PostgreSQL، تصاویر و `.env` موجود شما دست نمی‌زند. `.local/` در Git و Docker نادیده گرفته می‌شود؛ آن را منتشر نکنید.
- Redis، PostgreSQL، Docker، Celery worker و سرویس پیامکی برای این حالت لازم نیستند. کش در حافظه است؛ بعد از restart، OTP و محدودیت‌های موقت کش از نو شروع می‌شوند. این حالت را تک‌پردازشی اجرا کنید.
- پرداخت واقعی **غیرفعال** است، نه شبیه‌سازی پرداخت موفق. سبد، آدرس و ایجاد سفارش قابل تست‌اند؛ دکمهٔ پرداخت پیام غیرفعال‌بودن می‌دهد و سفارش پرداخت‌شده نمی‌شود. از پرداخت/رزرو دمو برای اطلاعات واقعی استفاده نکنید.
- زمان‌بندی Celery اجرا نمی‌شود. برای آزادسازی رزروهای منقضی: `python manage_laptop.py expire_orders`. این فرمان را در ترمینال سوم، در صورت نیاز اجرا کنید.
- `npm run dev:local` آدرس‌های `127.0.0.1:3000` و `127.0.0.1:8000` و هماهنگی حافظه‌ای را در همان پردازش فرانت تنظیم می‌کند. فایل‌های `.env` قبلی را بازنویسی نمی‌کند؛ secret محلی BFF جداست.

## ۱. دریافت نسخهٔ صحیح

از پوشه‌ای که `manage.py` و `frontend/` داخل آن‌اند، اگر تغییر محلی ذخیره‌نشده ندارید:

```powershell
git status
git fetch origin
git switch frontend/modern-redesign
git pull --ff-only origin frontend/modern-redesign
```

اگر Git دربارهٔ تغییرات محلی یا تعارض هشدار داد، متوقف شوید؛ `reset --hard` یا حذف فایل‌ها لازم نیست. این تغییرات در شاخهٔ بازطراحی هستند و تا ادغام PR لزوماً روی `main` نیستند.

## ۲. نصب یک‌بارهٔ بک‌اند

Python 3.12+ متناسب با Django 6 و Node.js 24 لازم‌اند. از ریشهٔ پروژه:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

اگر `.venv` سالم و وابستگی‌ها را قبلاً نصب کرده‌اید، ساخت محیط دوباره لازم نیست. فرمان‌های زیر Python همان محیط را صریحاً انتخاب می‌کنند، پس فعال‌سازی PowerShell و تغییر ExecutionPolicy لازم نیست.

## ۳. ساخت دیتابیس دمو و روشن‌کردن بک‌اند

ترمینال اول، از ریشهٔ پروژه:

```powershell
.\.venv\Scripts\python.exe manage_laptop.py migrate
.\.venv\Scripts\python.exe manage_laptop.py seed_demo
.\.venv\Scripts\python.exe manage_laptop.py runserver 127.0.0.1:8000
```

سید ۶ دسته، ۳۶ محصول، ۳۶ تصویر شماتیک محلی، ۹۶ تنوع رنگ/سایز، تخفیف و نمونه‌های ناموجود و کوپن `DEMO10` می‌سازد. داده‌ها، قیمت‌ها و تصاویر **ساختگی و با برچسب دمو** هستند؛ عکس کالای واقعی یا پیشنهاد فروش نیستند. تولید تصاویر کاملاً آفلاین و با Pillow است.

سید افزایشی است؛ اجرای دوباره محصول تکراری نمی‌سازد و موجودی/ویرایش محصولات قبلی را بازنشانی نمی‌کند. فقط در SQLite اختصاصی پروفایل لپ‌تاپ اجازهٔ اجرا دارد؛ برخورد نام/کد را بدون بازنویسی رد می‌کند. سفارش یا حساب با رمز پیش‌فرض ایجاد نمی‌کند.

برای پنل ادمین، اختیاری و با رمز انتخابی خودتان:

```powershell
.\.venv\Scripts\python.exe manage_laptop.py createsuperuser
```

پنل: http://127.0.0.1:8000/admin/

## ۴. روشن‌کردن فرانت

ترمینال دوم، از ریشهٔ پروژه:

```powershell
cd frontend
npm ci
npm run dev:local
```

`npm ci` فقط نصب اول یا بعد از تغییر وابستگی‌ها/lockfile است. اگر همین نسخهٔ پکیج‌ها قبلاً نصب شده، مستقیم `npm run dev:local` بزنید. هر دو ترمینال باید باز بمانند.

**سایت: http://127.0.0.1:3000** — برای سازگاری کوکی‌ها از همین آدرس استفاده کنید، نه ترکیبی از `localhost` و `127.0.0.1`.

## دفعات بعد

ترمینال اول از ریشه:

```powershell
.\.venv\Scripts\python.exe manage_laptop.py runserver 127.0.0.1:8000
```

ترمینال دوم از ریشه:

```powershell
cd frontend
npm run dev:local
```

فقط پس از دریافت migration جدید، دوباره `migrate` بزنید. برای ورود، شمارهٔ تست خود را وارد کنید و کد را از **ترمینال اول** بخوانید؛ پیامک ارسال نمی‌شود. شماره/کد یا secretها را به Git یا چت نفرستید. داده‌های دمو روی دیسک باقی می‌مانند.

## عیب‌یابی

- `SMS_IR_API_KEY` هنوز خواسته می‌شود؟ به احتمال زیاد `manage.py` عادی یا تنظیمات قدیمی اجرا شده؛ فرمان `manage_laptop.py` بالا را از ریشه اجرا کنید. provider پیامک و کنترل امنیتی production عمداً حذف نشده‌اند.
- `503`؟ Django باید روی 8000 روشن باشد؛ فرانت را با `dev:local` اجرا کنید، نه `dev` با env قدیمی Redis. راه‌اندازی سرویس‌های اجراشدهٔ قبلی را با `Ctrl+C` متوقف و دوباره اجرا کنید.
- پورت اشغال است؟ سرور قبلی همین پروژه را متوقف کنید. این پروفایل عمداً پورت‌های 3000/8000 را ثابت و هماهنگ انتخاب می‌کند.
- `429`؟ مهلت نمایش‌داده‌شده را صبر کنید؛ rate limit و اعتبارسنجی OTP حذف نشده‌اند. عکس کارت‌ها اکنون در پاسخ فهرست می‌آید و برای هر کارت درخواست جزئیات جدا ارسال نمی‌شود.
- Hydration با `data-bidi`؟ یک مرورگر/پروفایل بدون افزونه آزمایش کنید؛ روی لپ‌تاپ شما علت قطعی هنوز تأیید نشده است.
- این مسیر برای `npm run build/start` نیست؛ تولید همچنان Redis/HTTPS و تنظیمات مستقل امن می‌خواهد. `laptop_settings` را deploy نکنید.
